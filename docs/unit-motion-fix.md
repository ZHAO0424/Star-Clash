## 2. 「重族」移动一卡一卡、穿模

「重族」有两种读法，都查了:① 重型 / 巨型单位(坦克、攻城车、吞噬者、恶魔构造体);② 语音识别把「虫族」听成「重族」(虫群势力的工虫 / 母虫 / 幼虫群都是 Tripo 程序化预设动作)。两条线都有问题，下面一起修。

### 怎么测的

临时脚本(不入库，放在系统临时目录):无头 Chrome 打开 `?debug` 人机局，停掉主循环，**固定 1/60 秒步长手动推进**模拟 + `scene.syncUnits`(`performance.now` 换成假时钟);模拟和渲染各用一个固定种子的随机数，渲染改动不会让对局轨迹分叉 —— 修前修后比较的是同一段(帧数、位置逐帧一致)。场景熔岩锻炉，双方各放坦克 / 攻城车 / 吞噬者 / 构造体 + 步兵对照，跑 1500 帧(25 秒),逐帧记录逻辑位置、网格位置、朝向、车身高度、骨骼位置、包围盒。

- 联机模式：同一局当服务器，每 3 帧(50ms)`makeSnapshot → JSON → applySnapshot` 到镜像 Game,到达时间加 0–20ms 随机抖动，镜像每帧 `interpolate` 后渲染。
- 动作采样：九种单位一字排开、只有它们自己在走(关掉 AI),逐帧取骨骼在 body 局部坐标的位置(去掉整体平移 / 转向),「骨骼逐帧最大位移」超过中位数 4 倍记为尖峰;另取蒙皮后包围盒最低点 − 地面高度。

### 根因(按影响排序)

1. **循环动作接缝 + 预设毛刺(动作一卡一卡)**。Tripo 的行走片段首尾两帧不一样，`LoopRepeat` 每圈从末帧跳回首帧，差值在一帧里补完:
   - 六足 walk 预设(工虫、母虫):头 / 脊椎首尾差 **24°**(相邻帧中位 1.3°);而且片段是 3 段 0.83 秒步态拼起来的，每段开头 1–2 帧头和脊椎是另一个姿势(跳 24–32° 再跳回)→ **每 0.83 秒抽一下**。
   - 蛇形 march 预设(幼虫群):脊椎首尾差 **18°**(相邻帧中位 2.2°)。
   - 人形 walk(构造体、各势力步兵):腿部首尾差约 10°。构造体走得慢(动作 timeScale 0.69),接缝那一帧骨骼位移 0.144 格，是平时(0.021)的 7 倍，每 1.45 秒一次。
   - 实测尖峰数(300 帧):构造体 3、工虫 2、母虫 18、幼虫群 5、联盟步兵 2 → 修后全部 0(见图①)。
2. **重型载具程序化颠步**。坦克 / 攻城车 / 吞噬者是无骨骼模型，走路用 `|sin|` 上下颠 5cm + 左右摆 2.4°,每步落地是尖角(竖直速度突变),一辆车每秒蹦约 3 下 —— 25 秒里竖直速度突变 65 / 67 / 103 次。
3. **联机坐标量化(朝向来回摆)**。快照里单位坐标只保留 2 位小数;坦克每 50ms 只走 0.0175 格，被量化成 0.01 / 0.02 交替，斜着走时每份快照的方向来回跳，模型朝向跟着摆:朝向反转次数坦克 100、攻城车 130、构造体 149(本地模拟只有 9–25)。步兵走得快，相对误差小(37)—— 所以慢的重型单位最明显。
4. **脚陷进地里(穿模)**。模型按绑定姿势(T 字)的最低点贴地，但走 / 站姿势比绑定姿势低:工虫全程陷 4–10cm、虫族战士 6.6cm、幼虫群一半时间陷进去最深 6.7cm(见图②)。
5. **模型比碰撞圆大(和别的单位互相插入)**。所有地面单位碰撞半径都是 0.22(直径 0.44),坦克模型长 0.93。贴身时坦克的车头 / 车尾必然插进相邻单位的碰撞圆:25 秒里约 600–900 帧有轮廓点落进别的单位。这条**没改**(见文末)。
- 已排除：逻辑层的推挤 / 转向抖动。本地模拟里重型单位逐帧移动方向反转 0–2 次 / 25 秒，速度逐帧跳变 RMS 0.02–0.04(坦克、攻城车),和步兵同一水平;吞噬者 / 构造体偶发的大跳变是混战里被 `separate()` 推开或攻击前扑，不是持续抖动。

### 改法

| 问题 | 改动 | 文件 |
| --- | --- | --- |
| 接缝 / 毛刺 | 加载模型时对循环片段(walk / idle / run)做一次:Tripo 程序化预设(`preset:` 开头)先去毛刺(跳走又在 3 帧内跳回的关键帧，用前后好帧插值替换),再把首尾差按时间线性摊到整段(漂移校正),末帧 = 首帧。人形 walk 不去毛刺(脚趾一屈一伸是真动作,试过会被误伤) | 新增 `js/anim-loop.js`(纯函数，不依赖 three)+ `scene.js buildModel` |
| 载具颠步 | 重型档(`heavy`)无骨骼模型改成没有尖角的 `sin²` 起伏 1.2cm,不左右摆;步兵 / 立绘的颠步不变 | `scene.js syncUnits` |
| 联机量化 | 快照里单位 x / z 改保留 3 位小数(其它字段不变;每个单位每份快照多 2 个字符) | `js/net.js makeSnapshot` |
| 脚陷地 | 每种模型对 walk / idle 各采样一圈 16 个姿势的最低点，取第 3 低(约 1/8 分位)当地面;播哪个片段按哪个贴地，切换时平滑过渡 | `scene.js buildModel / animateModel` |

单测 `tests/anim-loop.test.mjs`:位移 / 四元数首尾对齐、单位长度、去毛刺只替换跳走又跳回的帧、连续大动作不动。

### 没解决 / 取舍

- **单位之间互相插入(根因 5)没改**。要根治得让碰撞半径跟体型走(坦克 0.22 → 约 0.4),但半径同时参与 `gap()` 射程判定、推挤、寻路和部署占位，属于玩法 / 平衡改动，需要先定。缩小 15% 后轮廓点落进邻居碰撞圆的帧数基本没变(坦克 920 → 939,攻城车 602 → 596)。
- **联机插值本身的顿挫**。客户端每收到快照都从「当前渲染位置」重新插值 50ms,到得晚就停在终点等、到得早就跳;实测所有单位(包括步兵)逐帧速度跳变 RMS 都在 0.45–0.55,修坐标精度后基本不变。这是全体单位共有的，不是重型特有的。根治需要换成「渲染延后约 100ms、在两份带时间戳的快照之间插值」的抖动缓冲，改动面较大，这次没做。
- 贴地取 1/8 分位是折中：整体上下起伏的幼虫群 / 工虫走路时大部分时间离地 3–4cm(修前是陷进去 5–10cm);构造体基本不变。
- 第一次生成某种带骨骼的模型时多做 32 次蒙皮包围盒采样(每种模型一次),可能有一次几十毫秒的卡顿，未在颈环 / XR 里测。
- 联机修复只在模拟快照里测过，没有在真实网络对局里验证。
