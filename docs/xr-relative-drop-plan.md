# XR 出牌 · 第十轮：手位选牌 + 抬起确认 + 落点跟手（2026-11-20，用户已确认方向，直接实现）

> 背景：第七～九轮的“手伸进棋盘 / 射线指落点”在眼镜里仍不顺手：要伸手、要瞄准、落点不稳。
> 用户提出：手左右移动切换牌；捏住后往上/前抬一段距离，落点出现在棋盘近边，之后随手移动。本方案在此基础上补细节。

## 1. 交互流程（手部追踪；手柄保留原射线方式）

| 阶段 | 输入 | 系统反馈 |
|-|-|-|
| **空闲** | 手不在手牌带内 | 无高亮 |
| **选牌** | 任一只手（捏合点）进入手牌带：牌行前后 ±12cm、上下 ±10cm、左右超出两端 6cm 以内 | 左右位置最近的牌抬起 1.5cm + 发光；相邻切换有 1.2cm 滞回，交界处不乱跳 |
| **抓起** | 捏合（不必碰到牌） | 牌跟手；显示“抬起出牌”小提示 |
| **确认** | 从抓起点往前/往上（沿“远离身体 + 向上”方向的合成位移）移动 ≥ **7cm** | 牌“脱手”飞到棋盘近边，出现落点标记 + 牌影 + 手→落点弧线；在 7cm 内松手 = 放回（取消，无提示） |
| **瞄准** | 手继续移动：左右 → 落点左右；前/上 → 落点推向对面；往回拉 → 落点拉回 | 落点平滑跟随（τ≈0.06s）；被石头/墙/占位挡住时吸到最近可放位，标记变色提示已吸附 |
| **出牌** | 松手 | 在落点出牌；手退回到确认线以内再松手 = 取消（放回） |

## 2. 映射（“虚拟触控板”，相对于确认时刻的手位）
- 坐标系：以棋盘为准（UI 换边时随之旋转），x = 棋盘左右，d = 棋盘纵深（远离玩家为正）。
- 确认瞬间记录手位 `h0`，落点初值 = 近边（d 取部署区近端 + 0.6 格）、x = 手当前左右位置对应的棋盘 x（手在牌行中间 = 棋盘中线）。
- 之后：`x = x0 + Δx_hand × GX`，`d = d0 + (Δforward + Δup × 0.8) × GD`
  - **GX**：手左右 ±15cm 覆盖整个场地宽度（场地半宽 4.8 格 → GX = 4.8 / 0.15 = 32 格/米）
  - **GD**：手前/上 20cm 推到己方部署区最远端（单位牌部署区纵深约 5.2 格 → GD ≈ 26 格/米）；法术牌同一增益但可推到全场
- 夹紧：单位 / 建筑牌夹在己方部署区内；法术牌夹在全场内。出界不再“无落点”，所以松手总能出牌（法力不足除外，提示并退回）。
- 吸附：沿用 `nearestDeploySpot` / 治疗吸附。

## 3. 保留与移除
- **移除（手部）**：射线抓牌、射线拖牌、拖牌上抬射线（DRAG_PITCH）、伸手投影落点（forwardLean / DROP_MAX_HEIGHT 路径）、磁吸 12cm 抓取（被手牌带选牌取代）。
- **保留**：手柄的射线抓放（原逻辑）；手部射线仍用于点按钮 / 面板（大厅、设置、强化、结算）；回收区：确认前把牌移到回收图标上松手 = 弃牌；落点锁存（150ms）仍作为追踪抖动兜底。
- 手牌行位置（第八轮：贴棋盘近边、不挡视线）不变。

## 4. 实现要点
- 纯函数（放 `js/xr-drop.js` 或 `xr-math.js`，全部单测）：
  - `pickCardByHand(handLocal, cardXs, current)` → 下标（含滞回、手牌带判定）
  - `liftProgress(h0, h, rowNormal)` → 0..1，≥1 即确认
  - `dropFromHand({ h0, h, x0, d0, gains, zone })` → 棋盘坐标（含夹紧）
- `xr.js`：手部输入走新状态机 `idle → select → held → aiming`；手柄维持旧逻辑。
- 反馈：牌抬起高亮、确认前的“抬起出牌”提示、牌影 + 弧线、吸附变色；i18n 中英。
- 第一局引导文案若提到“拖到战场”，同步改成“捏住抬起，移动手瞄准，松手出牌”。

## 5. 验收
- 单测：选牌滞回、手牌带外不选、确认阈值、映射增益与夹紧（单位 / 法术）、取消（确认前松手 / 退回确认线）。
- `tools/xr-harness.mjs` 增加新流程的脚本化检查（模拟手位序列 → 断言出牌位置）。
- 眼镜实测（用户）：连续 20 张，记录误选、取消、落点偏差的手感；GX / GD / 7cm 阈值按反馈调。
