### 为什么熔岩图的墙读成 m / n

量了三张图 `rockwall.glb` 的包围盒，根因有三个，叠在一起出现:

1. **模型长轴方向不统一，摆放代码却默认长轴是 X。**
   - 星核的 rockwall 是 1.0(X) × 0.4(Y) × 0.26(Z),长轴 X;熔岩的是 0.24 × 0.26 × **1.0(Z)**,长轴 Z。
   - `layoutProps` 统一按 `yaw + π/2` 旋转，所以熔岩的每块岩板都**横着**摆，和墙的走向垂直。
2. **按高度归一化缩放，扁平模型被放得过大。**
   - `flatten()` 把模型高度缩放到 `size=0.55`。熔岩岩板原高只有 0.26,于是放大 2.1 倍，**单块长约 2.1 格**。
   - 它们每 0.42 格放一块，互相重叠，叠成一排横杠。
3. **折线本身是 Z 字形，又做了镜像对称。**
   - 每段墙是 4 点之字线(左右摆动约 0.4)。横杠沿着之字线堆起来，再做中心对称，就成了 m 和 n。

还有一个**玩法层面**的问题：碰撞胶囊只有 0.57 宽，视觉上的墙却有约 2 格宽。玩家看到的「墙」比实际挡路的范围大 3 倍以上，会误判能不能走。

## 2. 方向

### 2.1 原则

- **玩法碰撞不动**:`map.js` 的 walls / obstacles / rifts / node 坐标和半径都不改，只换外观。需要动玩法的地方在 2.4 单独列出，默认不做。
- **外观贴合碰撞**:墙的视觉占地 = 胶囊宽 ±0.08,高度 0.35–0.5。比单位(0.8–1.2)矮，俯视镜头下不遮挡单位。上线前用脚本自动核对。
- **障碍改成模块化套件，不再沿折线堆模型**:每段折线拆成「直段 + 拐角接头 + 两端收头」。直段按长度挑 0.6 / 0.9 / 1.2 三种规格，拐角用接头块把折角吃掉。这样墙的形状是设计出来的，不再是串珠。
- **分层**(从里到外):

| 层 | 范围 | 内容 | 规则 |
| --- | --- | --- | --- |
| L0 玩法层 | 战场内 \|x\|<4.8、\|z\|<6.8 | 墙 / 岩石 / 裂隙池沿 | 低饱和、哑光，读形体不读花纹;交战区只允许地面贴花 |
| L1 边缘装饰 | 战场外沿 → 黄线内框(约 1.6 格宽) | 主题小物件 | 密度最高，用 InstancedMesh;靠镜头的一侧(+Z)限高 0.6 |
| L2 地标 | 台面四角外 / 远端两侧 | 每张图 1 个主地标 + 1–2 个次地标 | 用来讲主题，体量大但放在棋盘外 |
| L3 远景 | 现有 2D 全景(桌面 CSS / VR immersiveBackground) | 不动 | — |

- **密度**:边缘最密 → 裂隙外半圈中等 → 三条路和星核周围 0.6 格内零装饰。
- **眼镜**:黑 = 透明。地标和墙的主体保持中高亮度，暗部用补光托住，不靠暗色营造体积。

### 2.3 资产来源与预算

| 用途 | 来源 | 原因 |
| --- | --- | --- |
| 墙段 / 拐角 / 收头 / 岩柱 / 池沿 | **程序化 three.js**(新模块 `js/obstacle-kit.js`) | 尺寸必须精确贴合碰撞;8 张图共用同一套几何生成器，只换主题参数(截面轮廓、柱距、顶面细节、材质);可重跑，长轴方向、比例、地面对齐都由代码保证 |

**Tripo 生成规范**
- 请求必须带 `User-Agent` 头，否则会被 Cloudflare 拦截(403/1010)。
- 低多边形 + face limit,贴图降到 512(webp / jpg)。
- 生成脚本要放进本仓库 `tools/`(原来的 `gen-props.mjs` 不在这里)。

**导入规范**:每个模型入库时记录 `longAxis`、`footprint`、`height`。`flatten()` 改成按 footprint 归一化，不再只按高度。这一条就能直接修掉 m/n 根因的第 1、2 条。

## 3. 样板：熔岩锻炉

**为什么选它**:用户点名;已在可玩列表;问题最典型(m/n 墙、主题地标缺失);已有 forge / cone 模型可评估复用。

### 步骤(每步截图自检)

1. **导入规范**:`flatten()` 统一长轴、按 footprint 缩放，加一个尺寸检查函数。先确认 m/n 消失。
2. **`obstacle-kit.js`**:玄武岩六棱柱墙段(0.6 / 0.9 / 1.2)+ 拐角接头 + 收头 + 熔渣堆岩石 + 冷却岩壳池沿;全部 InstancedMesh。
3. **熔岩池着色器**:UV 流动 + 岩壳边暗化。熔岩河放在棋盘边缘(L1)。
4. **地标**:评估 `forge.glb`;不够就用 Tripo 生成敌方后方的大锻炉，加炉口发光和一点烟雾粒子。
5. **边缘装饰重排**:按密度规则摆放，交战区清空。

### 验收标准

| 项 | 标准 |
| --- | --- |
| 形体读感 | 桌面俯视截图里墙读成「连续的玄武岩矮墙」;找 3 个人看图，没有人说像字母 |
| 外观贴合碰撞 | 脚本检查每个墙实例包围盒与碰撞胶囊的偏差 ≤ 0.08;墙高 ≤ 0.5 |
| 交战区干净 | 三条路中心线和星核周围 0.6 格内没有 L1 装饰(脚本检查) |
| 主题可辨 | 第一眼能认出「锻炉 / 熔岩」,地标在桌面和 XR 默认视角下都可见 |
| 性能(XR 口径) | draw calls ≤ 235,三角形 ≤ 40 万，新增贴图 ≤ 4MB |
| 评分 | scorecard 的 World、Art direction ≥ 2.5,Materials ≥ 2 |
| 回归 | `npm test` 通过;`map.js` 不变(或按 2.4 单独审批);桌面 + 眼镜真机(AR 与 VR 各一张)截图 |

**做了什么**
- **墙**:全部换成玄武岩六棱柱。直段三列错位(中列 0.36–0.48 高、两侧 0.22–0.34)、拐角接头(中心高柱 + 外侧圆弧补柱 + 内角补柱)、两端收头(半圆渐低);约两成柱子顶面露出熔芯(按实例自发光，缓慢呼吸)。
- **岩石障碍**:中心高柱 + 9 根外倾断柱的熔渣堆，贴合 r=0.30 的圆。
- **熔岩池**:池沿两圈扁平六边形冷却岩板(≤0.06 高，读成地面不读成墙)。
- **边缘 L1(密)**:两条熔岩河从锻炉两侧流出，沿远端拐到两条长边一直流到近端(流动着色器：热核 + 漂移的冷却壳 + 两岸变暗);河岸岩壳、长边外沿石柱群(留空当)、近端低矮石柱(≤0.6)、远端锻炉两侧石柱、长边中段矿车轨道 + 3 辆矿车、铁砧 ×4、火盆 ×12、远端右角一座火山锥(复用 `cone.glb`)。
- **地标 L2**:敌方后方台面边缘的程序化大锻炉(八角收分炉身 + 炉罩 + 两侧六角窑 + 两根烟囱 + 铁箍;炉口 / 窑口 / 烟囱口 / 两圈熔缝发光;烟由 Points 着色器驱动，不占 CPU)。没调外部生成服务。

### 第二轮：两侧地形(2026-11-16)

用户反馈:「两边起伏的山很不正常、很突兀」(见 `overhaul-volcano-after.png` 两条长边的土丘)。参考自走棋类棋盘的设计原则(只借原则，不借资产 / 造型):玩法区绝对平整;高差只用在玩法区外，而且是有意的台阶 / 崖壁;有清晰的台沿把玩法区和装饰区分开;装饰低饱和、地标集中在远端;四周收边干净，像一块摆在托盘上的模型。

**鼓包来源**(脚本解析 `battlefield.glb` 顶点得出)
- 来自地形 GLB 的 **Island 网格**,不是 Rocks 网格、不是 `drape`。`build_terrain.py` 按 `relief` 风格(熔岩 = `'cones'`)在战场外圈(战场边 → 黄线，长边约 1.6 格宽)生成起伏：熔岩最高 1.68、星核 1.36、冰封 1.94;战场边外 0–0.42 还有一圈约 0.3 高的路缘隆起。

- `heightmap.json` 只覆盖 ±5.2 × ±7.2,**不含**这一圈;`heightAt` 在外面取边缘值，所以上一轮的熔岩河、石柱都按 ≈0 高度摆，被土丘埋掉一部分。

**做法**(只动熔岩图;判定条件 `hasDressing(id)`,其余 7 张不经过这段代码)

2. **台地**(`obstacle-layout.terraceBlocks`,纯数据;`obstacle-kit.terraceMesh` 渲染):倒角矩形挤出，合并成 1 个网格。

#### 画面做法

1. **切割六棱柱台地**(`obstacle-layout.terraceBlocks / cutColumnsLayout`,`obstacle-kit.cutColumnsMesh`)
   - 做法：全局一张蜂窝格。台地柱外接圆半径 0.14,场内柱 0.085。每块台地是凸多边形(倒角矩形);每个格子的六边形按所在块的边界做 Sutherland–Hodgman 裁切，落在边界上的边标成切面。外缘、台沿内缘(战场边)、台地之间的崖壁、河床壁都因此是一条直线 / 直角，没有锯齿。被更高的块整个盖住的格子不生成。
   - 台沿上为边河切出河床，再切出锻炉瀑布穿过外侧窄条的缺口和场内熔岩河的两个出水口。
   - 着色:
     - 柱顶格缝按**原六边形**算，所以被切开的半根柱子顶上不会多出一条缝;
     - 原生柱面偏暗，带竖纹;
     - 切面更亮、有细颗粒，柱与柱之间的缝更深，顶上一道亮边(读成「切开的玄武岩柱露出截面」);
     - 外侧是熔岩的切面，底部按离熔岩面的高度发红。
   - 上一轮散落的河岸岩板、溅落岩壳、近端矮岩板、长边 / 远端石柱群全部去掉。石柱群改成台地外圈的**整格柱抬高**:只抬完整的、不碰切面的格子，所以外缘那条线保持干净。抬高的柱子避开配景、轨道和锻炉;近端离地 ≤ 0.6。
   - 全部合并成 1 个网格。
2. **场内熔岩河**
   - 地形:Island 网格和高度图按新 `fieldHeight` 整形。河道低 0.11(单位蹚在熔岩里，脚没进熔岩面);岩桥处不挖;祭坛处是半径 1.25 的平台，顶 +0.21。
   - 两岸是 0.2 宽的切割细柱岸沿，比地面高 4.5 cm;岩桥是与地面齐平的玄武岩桥面，零星柱缝发红;祭坛台是圆形柱阵，熔岩从台下穿过，台边底部被熔岩映红。
   - 熔岩来源：两条边河在 z≈0 处各分出一股，穿过台沿出水口落进河道，沿中心线流到祭坛台下面(左右两股旋转对称)。
   - 着色器:
     - 流向:uv 沿河长度，纹理往下游漂;
     - 亮核：河心更黄更亮;
     - 暗壳：随流漂移的冷却壳，壳缝发亮;
     - 两岸压暗，再加顺流的细亮纹。
     - 颜色改成按线性空间写(上一轮按 sRGB 值写进 ShaderMaterial,输出时又转了一次 sRGB,所以发白)。现在主体是 sRGB≈(1, 0.45, 0.08) 的饱和橙，暗壳 ≈(0.45, 0.12, 0.05),不压成黑(眼镜里黑 = 透明)。
   - 热浪：河道上方一层加色热光(比河道宽 1.7 倍，噪声缓慢起伏);沿所有熔岩河撒火星 Points,上升、闪烁、淡出。两者各 1 次 draw call,都由着色器驱动。
3. **单位烧灼表现**(`scene.js`)
   - 单位身上橙红闪烁染色，冒火星。
   - 每跳一个小号橙色「−4」(不走 60 点的合并阈值，不闪白);烧灼时显示血条。
4. **部署提示**
