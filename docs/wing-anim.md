# 飞行牌翅膀骨骼动画:虚空蝠 / 飞翼虫(2026-11-17)

之前 `chaos_bats.glb`(虚空蝠)和 `swarm_flyer.glb`(飞翼虫)是 Tripo 出的刚体模型(`rig: 'rigid', clips: []`),翅膀不动,只靠代码让整只上下浮动。这次用 Blender 无头脚本给两只模型加了翅膀骨骼、蒙皮和四个动作。无人机(mecha_drone / mecha_swarmdrone)不在这次范围内。

## 结果

| 动作 | 时长 | 内容 | 游戏里什么时候播 |
| --- | --- | --- | --- |
| `fly` | 蝠 0.5s / 虫 0.4s,循环 | 一拍:下扑占 40%(快)、上抬占 60%(慢);下扑时翼尖往前兜、上抬时往后收;身体随扇翅轻微起伏 | 移动和站着都播这一个(代替 walk / idle) |
| `attack` | 0.5s | 0–30% 蓄力(翅膀高举、身体后仰后撤)→ 30–55% 猛扑(翅膀扇到底并前兜、身体前冲低头)→ 回到 fly 第 0 帧 | 攻击事件,`playOnce` 按攻击间隔加速 |
| `hurt` | 0.3s | 往后一缩 + 左右抖动(衰减),翅膀往上一收 | 单次伤害 > 60 |
| `die` | 1.0s | 前 35% 翅膀收起贴背,随后身体低头翻滚、加速下坠(模型单位 0.6);停在最后一帧 | 死亡,之后照旧下沉淡出 |

- fly 首尾两帧完全相同(实测所有轨道首尾差 0),60fps 下相邻帧最大转角 蝠 9.9° / 虫 10.5°(出现在快速下扑段),没有跳帧。
- attack / hurt 的首尾都是 fly 第 0 帧(翅膀在最高点),和循环之间的淡入淡出不会跳。
- 三角面不变(蝠 4841、虫 4944)。贴图是原来那张 JPEG,逐字节相同,没有重新压缩。
- 体积:蝠 319,440 → 405,228 字节(+27%),虫 298,632 → 379,492(+27%)。增加的部分基本都是蒙皮必需的数据:每个顶点的骨骼索引(4 字节)和权重(4 字节)约 58KB,加上动画和 JSON 约 25KB。Blender 导出的权重是 float32(16 字节/顶点),如果不处理会是 +54%,所以脚本导出后把权重改成了归一化 uint8(glTF 规范允许,three.js 直接支持),每个顶点的四个权重加起来仍然是 255。

## 做法

脚本 `tools/blender/wing_anim.py`,输入是原来的无骨骼 glb,输出是带骨骼和动画的 glb,可以重复跑。

```bash
"C:/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b --factory-startup \
    -P tools/blender/wing_anim.py -- chaos_bats  <原始 chaos_bats.glb>  assets/models/chaos_bats.glb  [报告.json] [预览前缀]
"C:/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b --factory-startup \
    -P tools/blender/wing_anim.py -- swarm_flyer <原始 swarm_flyer.glb> assets/models/swarm_flyer.glb [报告.json] [预览前缀]
```

- **输入必须是原始的无骨骼 glb**,不能拿已经处理过的输出再跑一遍。原始文件在 git 历史里(`git show ad77e86:assets/models/chaos_bats.glb > 原始.glb`)。
- 用 4.5 桌面版的绝对路径(有输出,能看到报错);商店版的 `blender-launcher` 别名在 Git Bash 里会什么都不做。
- 报告 JSON:量出来的骨骼位置、各骨骼的顶点数、片段帧数、前后字节数。预览前缀:额外用 Workbench 渲一张权重着色图和每个动作 6 帧。
- 参数都在脚本顶部的 `MODELS` 里(扇翅角度、周期、前冲距离等),改完重跑就行。

### 坐标

Blender 导入 glTF 后:+X 是模型正面(models.json 里的 `yaw: -1.5708` 把它转到游戏的前进方向),+Z 是上,+Y 是模型自己的左边。两只模型都是「正面朝前、翅膀往两侧展开」的姿势,翅膀膜面在 YZ 平面上。

动作都按左翼(+Y)在骨架空间里写,右翼用镜像四元数 `(w, -x, y, -z)` 自动生成,所以左右严格对称。骨骼的局部轴不靠猜:骨架空间的旋转 q 换成骨骼局部旋转用 `R_rest⁻¹ · q · R_rest`(`R_rest` 取自 `bone.matrix_local`)。

### 骨骼和权重

先测几何、再搭骨。两种翅膀做法不同:

**虚空蝠(膜翼,和身体连在一起)**:身体一根骨,每侧两节(上臂 `wing1` + 前臂 `wing2`)。

- 身体半宽 `root_y = 0.10`,是从正面正交图上量的,头、耳、躯干都在 ±0.10 以内。
- 翼根、翼肘、翼尖的高度和前后位置,由脚本按 |Y| 切片取翅膀顶点的 (x, z) 中位数,左右两侧合在一起算(所以天然对称)。实测:翼根 (−0.042, ±0.110, 0.015),翼肘 (−0.038, ±0.300, 0.112),翼尖 (−0.050, ±0.499, 0.021)。
- 权重只按顶点位置算:翅膀权重 = smoothstep(0.10 → 0.17, |Y|),上臂和前臂在翼肘 ±0.05 内过渡;身体下方的脚爪(z < −0.16,|Y| < 0.22)强制归身体。
- **为什么不用自动权重**:Tripo 网格是按 UV 缝切开的三角面片(7255 个顶点分成 1319 个连通块),热扩散自动权重在这种网格上会出错。只按位置算的话,缝两边位置相同的顶点权重一定相同,不会裂开。
- 左右两侧的顶点数不一样(左翼约 1270 个、右翼约 2600 个),这是原模型网格本身左右密度不同,骨骼和动作还是对称的。

**飞翼虫(硬翅,前后两对)**:身体一根骨,每片翅膀一根骨(`fore_L/R`、`hind_L/R`)。

- 按网格连通块分类:X 方向很薄(< 0.11)、在胸部上方(z > 0.07)往两侧伸出(|Y| > 0.10)的块是翅膀;再用 `z > 0.10 + 0.25·|Y|` 区分前翅(往上斜)和后翅(接近水平)。结果:前翅 430 个顶点,后翅 131 个,身体 6102 个。权重着色图确认分类干净,钳子、触角、背甲没有被分进翅膀。
- 翅膀整块刚性跟随骨骼(硬翅本来就不弯);翼根取离中线最近的 6% 顶点的质心,翼尖取离翼根最远的 6%。实测:前翅 根 (0.002, ±0.076, 0.161) → 尖 (0.081, ±0.497, 0.339);后翅 根 (−0.010, ±0.108, 0.134) → 尖 (0.025, ±0.455, 0.100)。
- 后翅比前翅幅度小 15%,相位慢 12%,前后翅不同步,看起来像昆虫。

### 动作参数(`MODELS`)

| | 虚空蝠 | 飞翼虫 |
| --- | --- | --- |
| fly 周期 | 0.5s | 0.4s |
| 上扬 / 下扑角(绕前进轴) | 38° / 34° | 22° / 40° |
| 前后扫(绕竖直轴) | ±13° | ±9° |
| 其它 | 前臂相对上臂再多扇 0.55 倍、相位慢 9%,上抬时往回收 22° | 后翅幅度 0.85、相位慢 12% |
| 身体起伏 | 0.018 | 0.014 |
| attack 前冲 / 低头 | 0.16 / 28° | 0.14 / 32° |
| die 下坠 | 0.6 | 0.6 |

(长度单位都是模型原始单位;游戏里模型缩放约 0.9–0.95。)

扇翅角度曲线:`p` 是一拍内的进度(0–1),0 是最高点;0–0.4 用余弦缓动从最高点到最低点,0.4–1 再回到最高点。两端的导数都是 0,所以首尾闭合而且速度连续。

## 接进游戏

改动只有 `js/scene.js` 和 `assets/models/models.json` 的两个条目:

1. `clipKey()` 加了 `fly` 这个名字。
2. `buildModel`:有 `fly` 的模型,walk 和 idle 都指向 fly 这同一个动作。移动和站立之间不切换动作,一直平稳地扇。fly 和其它循环片段一样走一遍首尾对齐(本来就是闭合的,这一步不会改动数据)。
3. 贴地采样(`entry.floors`)跳过 fly 片段。飞行单位离地多高由 `lift`(0.75)决定,模型按绑定姿势对齐;如果照常采样,下扑时最低的翼尖会被当成「脚底」,整只单位会被往上顶。跳过之后 `floorY` 不会被设置,root 一直保持在绑定姿势的位置,不会被拉回地面。
4. `animateModel`:按移动速度改播放速度(timeScale)只对真正的 walk 生效。fly 同时也是 idle,站着的时候不应该被减速到 0.6 倍。
5. `models.json`:两个条目改成 `rig: "winged"`,`clips: ["fly","attack","hurt","die"]`。`rig` 只在 `unit-size.js` 和占地上限里用来判断是不是 `biped`,改成 `winged` 后体型分档(飞行档)和缩放都和原来一样。

**和程序化浮动叠加**:`syncUnits` 里飞行单位 `body.position.y = baseY + sin(now/300 + id) × 0.05`(大约 1.9 秒一个周期)没有动。fly 片段里身体的起伏作用在骨骼 root 上(模型内部),幅度约 1.5cm、频率是扇翅频率,两者是相加的,不冲突:慢的整体飘浮上叠一层随扇翅的小颠动。刚体时代的程序化颠步和左右摆只对没有骨骼动画的模型生效,现在两只都有骨骼了,这部分自动不再作用(飞行单位原本就不颠步)。

`npm test` 96 项全部通过。

## 取舍 / 没做的

- **体积 +27%**:这是蒙皮的固定成本(每个顶点 8 字节),已经把 float 权重压成了 uint8;再往下压就要量化位置或法线,那会改动几何,这次没做。
- **蝙蝠的姿势是正面展翅的「挂墙」姿势**(翅膀膜面朝前),不是真蝙蝠水平飞行的姿态。扇翅主要是绕前进轴上下摆,再叠加前后扫,让俯视角也能看出翅膀在动。正侧面看,膜面有一部分是在自身平面里转动,不如水平膜翼那么明显。要彻底解决得把模型重新摆成水平飞行姿势,那就超出「只加骨骼」的范围了。
- **die 的下坠是写死在片段里的 0.6 模型单位**(约 0.55 格),和游戏里飞行高度 0.75 加上尸体下沉 0.35 大致对上,但不是精确落地;没有改尸体逻辑。
- 一张虚空蝠牌出 2 只,两只播放的动作完全一样,相位也一样(都从 fly 第 0 帧开始)。程序化浮动按单位 id 有相位差,所以整体看起来不会完全同步,但翅膀是同步扇的。如果需要错开,可以在 `animateModel` 第一次播 fly 时设一个随机的起始时间,这次没做。
- 帧序列截图里的时间是用 `mixer.setTime` 设的,不是实际播放;实际播放走的还是原来的状态机(`playOnce` 的攻击加速等)。没有在眼镜 / 颈环上验证过。
