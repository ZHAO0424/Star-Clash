# XR 手部交互升级 · Research + Plan

> 2026-11-16 · 状态：**已实现（未上机验证）** · 批注按推荐值定稿；P0–P5 已本地提交，未推送
> 需求（用户原话整理）：
> 1. 手的模型换成类似 VITURE 或其他项目里的完整半透明手模型。
> 2. 左手手心菜单：放重定位、暂停、设置等快捷按钮图标。
> 3. 双手 pinch 长按，可以旋转、升高、降低视角（摄像机位置）。
> 4. 远处的按钮要有从手中射出的射线。
> 参考：webxr 插件、之前做过的手交互。

## 三、Plan

### 3.1 模块划分（为可替换而设计，`xr.js` 只做接线）

| 新模块 | 职责 | 对外接口 |
|-|-|-|
| `js/xr-hand-visual.js` | 加载本地 generic-hand glb，换成半透明菲涅尔材质；按状态改颜色（悬停 / 捏合 / 抓牌） | `createHandVisual(xrHand, side)` → `{ object, setState(s) }` |
| `js/xr-hand-ray.js` | 每只手一根射线：`targetRaySpace` + One Euro 滤波；决定什么时候显示；光标点 | `update(frame) → { origin, dir, visible }`、`setHit(point \| null)` |
| `js/xr-palm-menu.js` | 掌心朝向判定（带回差 + 张开度）、菜单面板（canvas 纹理）、按钮命中 | `update(leftHand, head, rayR) → action \| null`、`open` |
| `js/xr-board-rig.js` | 双手长按操控：旋转、升降、推拉；橡皮筋；持久化 | `begin(hands) / update(hands) / end()`、`reset()` |
| 纯函数 `js/xr-math.js` | 掌心法线、回差、操控增量计算（不依赖 three 场景，方便测试） | 供上面几个模块调用 |

### 3.2 各需求的做法

**① 半透明手**
- 把 generic-hand 的 `left.glb` / `right.glb` 放进 `assets/hands/`，附 MIT 许可声明，不从 jsDelivr 在线拉（国内网络不稳，眼镜上也可能断网）。
- 材质：透明、`depthWrite:false`、基础 opacity 0.35 + 菲涅尔边缘光（自写 `ShaderMaterial` 或 `onBeforeCompile`）。`renderOrder` 排在场景之后、UI 面板（20）之前。
- 状态反馈：捏合时边缘光变亮；抓着牌时带势力色。
- 保留指尖光标小球（命中反馈要用）；关节小球去掉。
- 联机的对手手（`xr-avatar.js`）这次不改。

**② 左手手心菜单**
- 出现条件：左手掌心朝头（点积 >0.55 出现、<0.25 消失）且手掌张开；抓着牌、双手操控中时不出现。
- 位置：左手小指一侧、中指掌骨处，沿掌心偏 5cm、往上偏 7cm，跟手平滑。
- 按钮（一行图标，每个约 3cm，下面配小字）：**重定位 · 暂停 / 继续 · 设置 · 退出对局**。
- 点按：右手**直接戳**（指尖进入按钮 2cm 内）或者右手**射线 + 捏合**，两种都行；用上一帧的悬停目标。
- 暂停：本地人机对局暂停 `session.tick`，场景上盖「已暂停」提示；**联机对局按钮置灰**（服务器不支持暂停，这次不改服务器）。
- 设置：弹出一块 XR 设置面板，挂在世界里、手牌上方，包括棋盘尺寸、音效、手模型透明度（3 档），以及「视角复位」（把操控过的战场位置清零）。复用 `cb.onBattleAction`。
- 新图标：暂停、继续、设置 3 张，风格照 `assets/ui/xr/`（黑底发光、滤色混合）。由 AI 画图出，或者先用矢量图标顶上。

**③ 双手长按操控视角**
- 手势：两只手都捏合（空捏，没抓牌）并保持 **0.4s** → 进入操控模式（两手之间出现一条连线，战场边缘发光提示）。之后：
  - **旋转**：两手连线在水平面上转了多少度，战场就绕自身中心转多少度；
  - **升降**：两手中点上下移动 → 战场高度，增益 1，限制在头下 0.2m 到 0.8m；
  - **推拉**：两手中点前后移动 → 战场沿水平方向远近，深度增益 1.5，限制 0.45m 到 1.1m。
  - 松开任一只手结束；越界的部分松手后用橡皮筋弹回边界。
- **和现在的「双手空捏 1s 重定位」冲突**：建议把重定位**挪进手心菜单**，双手长按专门用来操控。（备选：捏住不动满 1.2s 才算重定位，一动就进入操控。）
- 变换施加在新加的 `boardRig` 节点上，插在 `anchor` 和 `world` 之间：
  - 手牌和 HUD 留在原地，伸手可及；
  - `applyBoardSize` 对 world 的改动不受影响；
  - 落位检测和联机姿态归一化改用 world 的世界矩阵（要回归测试）。
- 操控结果存进 `prefs`；重定位时保留，「视角复位」才清零。

**④ 手部射线**
- 射线来源：`targetRaySpace`，One Euro 滤波。
- 什么时候显示：手**不在**近距离目标附近（离手牌 / 按钮超过 15cm），并且射线指向一块可以交互的面板时，才显示射线和光标。近距离时保持现在的戳和抓。
- 射线能点的东西：大厅按钮、HUD / 战斗按钮、强化面板、结束面板、设置面板；**不能拖牌**（拖牌保持近手操作，以免误出牌）。
- 两只手同时只显示一根，另一只手捏一下就抢过来；手心菜单出现时，左手射线隐藏。
- 手柄的射线兜底保留。

### 3.5 P5（追加）· 桌面鼠标视角

- 原实现：`js/scene.js` 的 `enableMouseView()`（自写，不是 OrbitControls）。原映射：右键拖动 = 旋转（yaw ±1.3、pitch −0.45~0.4，俯角再夹在 0.62~1.45 rad）；滚轮 = 缩放（zoom 0.55~1.6）；中键单击 = 复位；左键留给出牌；只认 `pointerType === 'mouse'`，触屏不受影响；`contextmenu` 已屏蔽。
- 改后：右键旋转、滚轮缩放保持原样和原限幅；**中键按住拖动 = 平移**（注视点在地面上移动，战场跟着光标走，注视点限制在战场范围 ±FIELD_W × ±FIELD_HALF 内——原来没有平移，限幅是新定的）；中键单击不动（<4px）仍是复位；`mousedown` 中键也 `preventDefault`，避免浏览器自动滚动。
- 平移在 `fitCamera` 取景算完后整体平移相机与注视点，不参与取景计算（否则又被居中抵消）；雾距离改按相机到注视点算。复位 / 换局时平移一起清零。
- 未在浏览器里实际操作验证。

### 3.6 上机验证清单（全部未做）

- 半透明手：glb 加载、材质替换后无报错，皮肤跟随正确，和面板没有排序闪烁；淡 / 中 / 浓三档观感。
- 射线：VITURE 的 `targetRaySpace` 方向是否合理（jelly-harbor 曾发现手部射线偏高 30°）；One Euro 参数；15cm 近手阈值；抢射线。
- 手心菜单：张开度 / 朝向阈值是合成手标定的，真机要调；戳和射线 + 捏合两种点法；左手捏合被吃掉不影响出牌。
- 暂停 / 继续、联机下置灰、退出对局二次确认。
- 双手操控方向、增益、限幅、橡皮筋；操控后落位格子正确；联机时对手看到的手 / 头位置正确（战场转过 90° 时对手 avatar 可能因 `xrPartInSeat` 被过滤）。
- `hand-tracking` 仍在 `optionalFeatures`，按计划留给上机时再决定是否改 required。

## 第三轮 · 眼镜验收反馈（11-16，第二轮 + 部署特效，主线 88b3fb8）· 已实现（未上机验证），实施记录见本节末尾

> 行号以 88b3fb8 为准。每条格式：原因 → 改法 → 验证；**【拍板】** 是需要用户定的点，括号里是推荐值。

### 1. 开局（大厅）UI 离得太近

- **原因**：大厅整组放在 `anchor` 前方 46cm、头下 14.5cm（`js/xr.js:270` `this.lobby.position.set(0, -0.145, -0.46)`）。这是第一轮之前为"伸手能戳到"定的距离；第二轮有了射线以后，没必要再贴在手边。46cm 也比眼镜舒适的聚焦距离（约 0.6–1m）近，看着压迫。
- **改法**：大厅组推到前方 0.65m、头下 0.20m，整组 `scale` 放大 1.3 倍，让视角大小基本不变（0.46→0.65 远了 1.41 倍，放大 1.3 倍后视角只小约 8%）。之后主要靠射线点，伸手够不到也没关系。教学（guide）面板在大厅组里，会一起挪。设置面板（`xr.js` 设置组，0.5m）在大厅里打开时，会和大厅错开前后，不用动。
- **验证**：Node 里核对大厅面板的世界坐标和视角；上机看距离是否舒服、射线能不能点到每个按钮。
- **【拍板】** 距离 0.65m（推荐）还是 0.75m；要不要同时放大（推荐放大 1.3 倍，否则字会变小）。

### 2. 「修复」类卡牌效果和范围太小，要自动找最近的受伤己方单位

- **现状（查清）**：
  - 只有钢铁的「装甲维修」`steel_repair` 属于修复类（`js/cards.js:59`），效果 `heal_all`，**本来就是全图生效**：己方所有单位回复 120 生命。不加建筑，也不加塔或核心（`js/game.js:288`，`mine` 过滤了 `building`）。它没有 `radius`，也没有 `needTarget`。
  - 但拖牌时预览圈用的是 `previewRadius` → `c.radius || 0.3`（`js/cards.js:213`），只画一个 0.3 的小圈（XR：`xr.js:892` 的 `bs.showPlacement`；桌面同一个函数）。特效也只是每个己方单位脚下一小撮绿色光点（`js/scene.js:1840`）。
  - 所以用户看到的"范围小"其实是**预览和特效在骗人**：实际效果是全图，但看起来只作用于手下一个小圈。同类的还有「全员强化」`steel_buff_atk`（`buff_atk`，也是全图，同样只显示 0.3 圈）。
  - 松手流程：拖到战场内任意位置松手就释放（`release` → `cb.onPlay(idx, x, z)`），落点对 `heal_all` 没有意义。
- **改法（两种，推荐 A）**：
  - **A. 不改平衡，只改表现（推荐）**：
    - 拖起这类"全体友军"法术（`heal_all` / `buff_atk`）时，自动找出**受伤的**己方单位（`hp < maxHp`；`buff_atk` 则是全部己方单位），在每个单位头顶挂一个绿色十字标记（强化用金色箭头）。离牌的落点最近的那个标记最大、带脉冲，作为"主目标"。
    - 隐藏 0.3 小圈；松手（在战场内任意位置）就释放。特效改成从主目标开始、沿各单位依次跳一条治疗光链，再加头顶十字闪，让"全体都加了"看得见。
    - 没有受伤单位时：标记换成灰色问号挂在手上的牌旁边，提示「没有受伤的单位」。仍然可以出（不拦，保持现有规则），或者 **【拍板】** 拦下不让出。
    - 这样不改 `game.js` 的数值，服务器共用的规则不受影响（`server/server.mjs:28` 直接用 `js/game.js`）。
  - **B. 改成单体 / 小范围治疗**：自动吸附最近的受伤单位，治疗它 + 半径 1.2 内的友军，数值上调。这是平衡改动，联机两端一起变，还要重调 AI（`js/ai.js` 的法术判断）。
  - **吸附范围（A、B 共用）**：主目标 = 离当前落点最近的受伤己方单位，全图搜，不设半径。拖牌时每帧重算，带 0.6 格滞回，防止两个目标之间来回跳。
  - **桌面版**：同一套逻辑放在 `scene.showPlacement` 里，桌面拖牌也显示头顶标记。推荐桌面同样适用，因为标记是在 3D 场景里画的，两端共用。
- **验证**：Node 单测：「找主目标 / 受伤过滤 / 滞回」写成纯函数测；本地人机对局里先让单位受伤，再拖维修，看标记和松手后的血量；上机看标记大小能不能看清。
- **【拍板】** A（只改表现，推荐）还是 B（改成范围治疗）；没有受伤单位时拦不拦（推荐不拦、只提示）；`buff_atk` 要不要一起做（推荐一起）。

### 3. 手牌和能量条太挡视线；能量条放手牌下面；卡面背景透明 / 半透明

- **原因**：
  - 手牌行在头下 34.5cm、前方 26.5cm，向后倾 0.5 rad（`js/xr.js:170-171`），在视线下方约 52°。能量条在手牌**上方** 7.1cm（`xr.js:189`），是整行最高的东西。
  - 战场近边在前方约 21cm、头下 50cm（标准棋盘半长 (9.4+0.42)×0.052≈0.51m，中心在 0.72m）。手牌行和能量条正好压在战场靠近自己的那一半上方。
  - 卡面底是不透明的紫色渐变（`xr.js:81-84` `drawCard`），整张牌挡住后面的战场。
- **改法**：
  - 手牌行下移、略后移：`cardRow` 改到 (0, −0.42, −0.24)，倾角 −0.6，在视线下方约 60°。
  - 能量条从 +0.071 挪到手牌下方 −0.072，也就是原来卡牌说明条的位置。卡牌说明条（`cardDetailPanel`，`xr.js:192`）改到能量条下方 −0.11，只在悬停 / 抓牌时出现。下一张预览、回收区位置不变。
  - 卡面底：渐变改成半透明，alpha 0.45。边框、费用、名字、立绘照常不透明，背后的战场能透出来。
  - 面板写深度（第二轮 R1，`alphaTest 0.05`）对半透明底没影响：alpha 0.45 > 0.05，仍然写深度，手和牌的前后遮挡关系不变。
  - 不能打出的牌原来整体 `globalAlpha 0.4`（`xr.js` `drawCard`），改成只压暗立绘和文字，否则太淡。

- **【拍板】** 卡面底半透明 0.45（推荐）还是全透明（全透明时字和边框在复杂地形上可能看不清）；手牌下移的幅度（推荐 −0.42 / 60°）。

### 4. 远处那排按钮并进左手手心菜单，那排去掉

### 5. 棋盘转过 45° 后，手牌和 HUD 自动换到面向用户的那一侧

- **和第二轮的关系**：第二轮 R1 把整套 UI 挂到 `boardRig.node` 下，"UI 与战场相对固定"（`js/xr.js` 构造函数里 `this.boardRig.node.add(this.ui / lobby / settings / poster)`）。所以现在转棋盘，手牌和 HUD 会跟着转走，转 90° 后手牌就跑到侧面去了。这一条是在"相对固定"上加一层**按 90° 扇区吸附**：平移照旧跟着战场走，旋转只取最接近用户的那条边。
- **规则**：
  - 在 `boardRig.node` 下加一个 `uiPivot` 节点，原点放在战场中心（`world.position`）。ui / lobby / settings / poster 改挂到它下面，各自的位置减去这个中心点，保证 `uiPivot` 不转时和现在一模一样。
  - 每帧算用户相对棋盘的朝向：`φ = wrap(头部水平朝向 − (anchor 朝向 + rig.yaw))`。用当前头部朝向，而不是 recenter 时的朝向，这样绕桌子走也对。
  - 扇区 `k = round(φ / 90°)`；`uiPivot` 的目标转角 = `k × 90°`，也就是 UI 转到面向用户的那条边。
  - 滞回：当前在扇区 k 时，`|φ − k·90°| > 45° + 10°` 才换；换完要回到 35° 以内才算稳定，避免在 45° 附近来回翻。
  - 冻结：抓着牌、双手操控进行中、手心菜单打开时都不换，免得牌在手里跳走；松手后再判断。
  - 动画：0.35s 缓出（ease-out cubic）。用 `uiPivot` 的 quaternion slerp 绕战场中心转，手牌、HUD、提示一起平滑转过去。
- **注意**：
  - 落位检测、射线命中都用世界坐标，不受影响。
  - 联机姿态按 boardRig 坐标归一化（`sendLocalPose`），和 UI 转到哪边无关，不变。
  - 但用户换到侧面坐时，头在 boardRig 坐标里就在侧面，`xrPartInSeat`（`js/net.js`）可能把对手看到的头 / 手过滤掉，这是已知限制。
  - 己方半场仍在 world 的 +z，换到侧面后自己的部署区在左手或右手边。这是转棋盘的本意，不处理。
- **验证**：
  - 先在 `js/xr-math.js` 加纯函数 `uiSector(φ, current, hysteresis)` 写单测：44° 不换、56° 换、换后 40° 不回、134°→k=1 等。
  - Node 数值验证：`uiPivot` 为 0 时 UI 世界矩阵与改前逐元素一致（同第二轮的验证办法）。
  - 上机转棋盘看切换时机和动画。
- **【拍板】** 吸附依据用当前头部朝向（推荐）还是只看 rig.yaw；滞回 10°（推荐）；HUD 是否也跟着换（推荐换，否则 HUD 会在用户侧面）。

### 6. Bug：打完一局 XR 卡住，没回到主菜单或结束界面

## 第四轮 · 眼镜验收反馈（第三轮 bcdca43 之后）· 已实现（未上机验证），实施记录见本节末尾

> 行号以 bcdca43 为准。尺寸单位：「格」= 战场坐标；XR 里标准棋盘 1 格 = 0.052m。每条格式：原因 → 推荐改法 → 验证 → **【拍板】**（括号里是推荐值）。

### 1. 大单位的部署特效太大

- **原因（查清）**：
  - 「锁定」法阵的半径用的是 `previewRadius(card)`（`js/cards.js:213`）。对单位来说它等于**攻击射程 + 体型**，不是部署半径，也不是体型：`c.range + 0.22`，建筑是 `c.range + 0.42`，有光环 / 脉冲的建筑用光环 / 脉冲半径。
  - 这个值经 `scene.showPlacement` 的 `marker` 分支（`js/scene.js:682`）传给 `DeployMarker.set`（`js/deploy-fx.js:232`），外圈、符文、脉冲都按它缩放（`deploy-fx.js:250-252, 278`）。
  - 所以远程单位的法阵特别大，和单位大小无关。例如：
    - 狙击单元射程 3.0 → 法阵半径 3.2 格，直径 6.4 格，战场全宽才 9.6 格（`js/cards.js:73`）；
    - 火炮哨站 2.8 → 3.0 格（`cards.js:53`）；
    - 防御炮台 2.6 + 0.42 ≈ 3.0 格。
  - 「降临」序列本身是固定尺寸（`js/scene.js:1987` `descendFx`：r 单位 0.7 / 建筑 1.0；`js/vfx.js:370-395`：冲击环 1.4 / 1.8、闪光 1.8 / 2.4、光柱宽 0.32 / 0.42），不随射程变，偏大但不离谱。
- **推荐改法**：
  - 法阵按**体型分 3 档**，不再用射程：
    - 小：普通单位、`count > 2` 的群兵，半径 0.55；
    - 中：费用 ≥ 5 的单位或空中单位，0.75；
    - 大：建筑，1.0。
  - 射程另外用一条细环表示（复用 `placeRing`，不透明度 0.35、不画面积填充），让玩家知道打多远，但不占视觉重心。
  - 「降临」的冲击环 / 闪光按同样 3 档的倍率缩放（小 0.75、中 1、大 1.2），上限就是现在的建筑尺寸。
- **验证**：Node 里对全部卡牌打印改前 / 改后的法阵半径，确认最大值 ≤ 1.0 格；桌面拖牌截图对比；上机看大单位。
- **【拍板】** 三档半径（0.55 / 0.75 / 1.0）；射程细环要不要（推荐要）；降临序列要不要一起按档缩（推荐要）。

### 2. 手误触变成射线，指到远处的信息面板

- **原因（查清）**：
  - 第二轮 R2 为了让光标"贴得上"，把一批**只显示、不能点**的面板放进了 `raySurfaces()`（`js/xr.js:1074`）：HUD、大厅标题、教学大图、设置标题、首局提示、暂停提示、能量条、下一张、卡牌说明、回收区、强化等待 / 倒计时。
  - `updatePointers`（`xr.js:1081`）里射线命中它们就算 `hitDistance`，传给 `CursorFx`，于是 `attached = true`。`HandRay.present` 里射线淡入的条件是 `seeking || fx.attached`（`js/xr-hand-ray.js:79`）。结果手随便一抬、射线扫过远处的 HUD，射线就亮出来。
  - 另外，"在指的那只手"只要离面板 / 手牌超过 15cm（`RAY_NEAR`，`xr.js:43`；`st.near`，`xr.js:1093`）就一直显示光标圈。远近切换没有回差，手在 15cm 附近晃动时会在"近手"和"射线"之间来回跳。
  - `HandArbiter` 只决定"哪只手指"，不判断"手是不是想指"。手垂在身侧、放在腿上时也会出光标。
- **推荐改法**：
  - **只有可交互目标才吸射线**：从命中列表里去掉 `raySurfaces()`，信息面板不再让光标贴上、不让射线淡入。光标贴面板和射线淡入，只认 `rayPanels()` 里能点的东西加上手心菜单。
  - **光标圈也改成按需显示**：指着可交互目标，或者正在找光标（`SeekDetector`）时才显示；空指时不显示，现在是空指也常显。
  - **远近切换加回差**：离面板 < 0.15m 进入近手，> 0.22m 才回到射线。
  - **手要"举起来"才算在指**：用 `HandArbiter` 里已有的头部坐标梯形区（`xr-pointer.js` `FLEX.ZONE_H / ZONE_F`），手低于头下 0.55m 或离头不到 0.1m 时不出射线。
  - **捏合点击要求已经悬停 ≥ 0.12s**，防止扫过按钮时顺手一捏就点上。
- **验证**：无头脚本（第三轮的手部模拟）里让手扫过 HUD，确认 `rayActive` 时 `hitDistance` 为 null、射线不亮；回差和举手区写纯函数单测；上机看误触率。
- **【拍板】** 空指时完全不显示光标圈（推荐不显示）；回差 0.15 / 0.22m；悬停 0.12s 的点击门槛要不要（推荐要）。

### 3. 选中牌后其余手牌直接渐隐；手牌不要被凹凸的棋盘边缘挡住

- **原因（查清）**：
  - 收起是第二轮 R3 的 `collapseCards`（`js/xr.js:1522`，`COLLAPSE_HEIGHT 0.12`，`xr.js:40`），按缩放压扁。
  - **遮挡**：第三轮把手牌行下移到 (0, −0.42, −0.24)、倾角 −0.6（`xr.js:179-180`）。算下来，标准棋盘的近边在 z = −0.72 + (9.4+0.42)×0.052 ≈ **−0.209**，台面在 y ≈ −0.5 + (−0.32)×0.052 ≈ **−0.517**。而：
    - 卡牌下沿在 (y −0.461, z −0.212)；
    - 能量条在 (−0.479, −0.20)；
    - 说明条在 (−0.51, −0.178)。
    
    这三样都贴着、甚至伸进棋盘近边上方，离台面只有 0.6–5cm。金色边框模型、地形起伏和近边的装饰物一高出台面就会挡住它们。
  - 第二轮 R1 起面板写深度、正常做深度测试，不透明的棋盘先画，挡住的部分面板就直接不画，看起来就是"牌被边缘啃掉一块"。
- **推荐改法**：
  - **渐隐代替压扁**：其余手牌的正面 / 背面材质 opacity 在 0.15s 内渐变到 0，然后 `visible = false`；松手后渐显。删掉 `collapseCards` 的缩放和下沉。
  - **几何上让开**：手牌行（含能量条、说明条）整体放在棋盘近边**外侧**，离边 ≥ 4cm，且高于台面 + 边框高度 ≥ 3cm。具体位置由第 5 条的自适应弧算，不再写死。
  - **兜底**：手牌行的面板 `depthTest: false`（仍然 `depthWrite`），永远画在棋盘之上。半透明手 renderOrder 40 晚于面板、读深度，手和牌的前后遮挡不受影响。
- **验证**：Node 里按三档棋盘尺寸和第 5 条的升降范围，核对手牌行每个面板四角都在近边外侧、高于台面；上机看凹凸地形。
- **【拍板】** 渐隐时长（推荐 0.15s）；要不要 depthTest 关的兜底（推荐要，地形和装饰物的高度没法逐个保证）。

### 4. 部署落点往手前方斜一点；被装饰挡住时就近找空位

- **原因（查清）**：
  - 近手拖牌的落点是把捏合点**竖直投影**到战场：`dragPoint` 里 `bs.worldPointToField(point)`（`js/xr.js:1281` → `js/scene.js:1610`，取战场本地 x/z）。所以要放到战场远处，手就得伸到远处正上方。
  - 被拒的落点直接失败：`deployBlockReason`（`js/game.js:122-137`）按顺序判断：出界 → 越过己方部署线 → 岩石 / 装饰障碍（`map.obstacles`，`js/map.js:33`，单位要离开 `o.r + 0.22 + ROCK_CLEARANCE`）→ 分路长墙（`wallGap < margin`）→ 建筑与塔 / 建筑重叠。服务器出牌时用同一个函数复核（`playCard` → `canDeployAt`，`game.js:157`；`server/server.mjs:28` 直接用 `js/game.js`）。
- **推荐改法**：
  - **前倾投影**：落点 = 捏合点竖直投影后，再沿「眼睛 → 手」的水平方向前推 `offset`：`offset = min(cap, λ · h · d / (yEye − yHand))`。其中 h 是手离台面的高度，d 是眼到手的水平距离，`yEye − yHand` 是眼高出手的高度。
    - 这相当于把「眼睛穿过指尖」的射线和台面的交点按 λ 混合：手越高、越靠前，偏得越多；手贴着台面时 offset → 0，和现在一样。
    - 推荐 λ = 0.6、cap = 0.12m（标准棋盘约 2.3 格），按 0.1s 平滑。
    - 牌和落点之间画一条细虚线，让玩家看到"落在那里"。
    - 射线拖牌不受影响（本来就是射线与台面的交点）。
  - **就近找空位**：在 `game.js` 加 `nearestDeploySpot(who, card, x, z, maxR = 1.0)`。
    - 只在原因为 `deployRock` / `deployWall` / `deployOccupied` 时搜索。出界、越过部署线照旧失败，因为那属于玩家意图错误。
    - 从近到远按同心圆采样：半径 0.15, 0.3, … 1.0 格，每圈 16 个方向，返回第一个 `deployBlockReason === null` 的点，同一圈里取离原点最近的。
    - 预览时法阵画在吸附后的位置，原落点到吸附点画一条细线。
    - 出牌时客户端先吸附，再把吸附后的坐标发给服务器（`NetSession.play(idx, x, z)`）。服务器用同一个 `deployBlockReason` 复核，必然一致；搜索本身不需要放到服务器。
    - 桌面版共用（`main.js:902` `playAt` 和 `showCardPlacement`）。
- **验证**：`nearestDeploySpot` 写单测：岩石边、墙边、建筑重叠、找不到时返回 null、结果必须 `canDeployAt`；前倾函数写纯函数单测（手贴台面 offset = 0、上限生效）；Node 里对每张地图在己方半场打格点，统计"原来失败、现在成功"的比例；上机看手感。
- **【拍板】** λ 0.6 / 上限 0.12m（推荐）；就近搜索半径 1.0 格（推荐）；越过部署线要不要也吸回线内（推荐不吸，保持失败提示）。

### 5. 手牌和能量条按棋盘高度自适应倾斜（以近边为圆心的弧）

- **现状**：手牌行位置和倾角写死在 `xr.js:179-180`。第二轮双手操控能把棋盘在头下 0.2–0.8m 之间升降（`xr-math.js` `RIG.HEIGHT`），但 UI 是和战场一起整体平移的，所以手牌和棋盘的相对位置不变，**相对眼睛的角度却变了**：棋盘抬高后手牌变得几乎平躺在视线前方，降低后又立得太高。
- **几何（在 UI 坐标系里算，也就是 `uiInner` 的本地坐标）**：
  - 近边点 `N = (0, yTop, zEdge)`：
    - `yTop` = 台面高度（`world.position.y + ARENA.top × scale`）+ 边框高度；
    - `zEdge = world.position.z + halfExtent`，其中 `halfExtent` 和第三轮的换边扇区有关：扇区 0 / 2 用 `(ARENA.hz + ARENA.rim) × scale`，扇区 1 / 3 面对的是棋盘侧边，用 `(ARENA.hx + ARENA.rim) × scale`。
  - 眼睛 `E` = 头部位置换到同一坐标系（`uiInner.worldToLocal(camera)`），平滑 0.25s。
  - 视线仰角 `β = atan2(E.y − N.y, E.z − N.z)`，就是从近边看眼睛的角度，限幅在 [25°, 70°]。
  - 手牌行中心放在以 N 为圆心、半径 R = 0.11m 的弧上，比视线方向往下压 δ = 35°（把手牌放在视线下方、近边外侧）：`P = N + R · (0, sin(β − δ), cos(β − δ))`。
  - 再约束 `P.y ≥ yTop + 0.03 + 卡高/2`、`P.z ≥ zEdge + 0.04`（第 3 条的防穿模条件）。
  - 倾角：手牌平面法线正对眼睛，`rotation.x = −(π/2 − atan2(E.y − P.y, E.z − P.z))`，限幅 [−1.0, −0.2] rad。
  - 所有量每帧算目标值，指数平滑（τ = 0.2s）；抓牌时冻结，免得牌在手里动。
- **和第三轮换边的组合**：手牌行仍在 `uiInner` 下，跟着 `uiPivot` 按 90° 吸附。上面的 N 和 halfExtent 在**换边之后的 UI 坐标**里算，所以换到侧边时弧心自动落在侧边，半宽换成侧边的。换边动画期间用目标扇区的 halfExtent，和转角一起平滑过去。
- **数值示例**（标准棋盘，近边 z = −0.209，眼在原点，边框高度暂按 0 算）：

  | 棋盘高度 | β | 手牌行中心 P (y, z) | 离眼距离 | 倾角 |
  |-|-|-|-|-|
  | 头下 0.5m（默认） | 68° | (−0.457, −0.117) | 0.47m | −0.25 rad |
  | 头下 0.2m（最高） | 46° | (−0.196, −0.101) | 0.22m | −0.47 rad |
  | 头下 0.8m（最低） | 76° → 限到 70° | (−0.754, −0.119) | 0.76m | −0.16 → 限到 −0.2 rad |

- **发现的矛盾**：近边离眼睛水平只有约 21cm，所以"手牌必须在近边外侧"和"手牌离眼睛不能太近"在棋盘抬到最高时冲突，算出来只剩 0.22m，太近、眼睛对不上焦。
  - 推荐再加一条**离眼 ≥ 0.32m**：不满足时沿弧往近边上方转，允许手牌悬在近边内侧的上空，靠第 3 条的 depthTest 关兜底不被挡。
  - 另一个办法是限制双手操控的最高高度，从头下 0.2m 改成 0.3m。
- **验证**：先写纯函数 `cardRowPose(eye, nearEdge, cardH)` → `{ y, z, tilt }` 加单测（限幅、单调、和近边 / 台面的间距）；Node 里扫棋盘高度 0.2–0.8m × 三档尺寸 × 两种边，打表核对不穿模；上机升降棋盘看效果。
- **【拍板】** R = 0.11m、δ = 35°（推荐，上机再调）；离眼太近时让手牌悬到近边上空（推荐），还是把棋盘最高限到头下 0.3m；HUD 要不要也做同样的自适应（推荐这次只做手牌行 + 能量条）；抓牌时冻结（推荐冻结）。
